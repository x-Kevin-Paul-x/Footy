# 01. System Architecture

## Overview
The **Footy Project** is a football management simulation that combines a Python-based simulation engine with a modern React frontend. The system allows users to simulate football seasons, manage teams, and view detailed statistics through a web interface.

## High-Level Architecture

The system follows a decoupled architecture where the simulation logic runs independently (or via API trigger) and stores data in an SQLite database and JSON report files. The frontend consumes this data via a FastAPI API.


## Key Components

### 1. Backend (Python)
The backend is responsible for the heavy lifting: running the football simulation, calculating match results, processing transfers, and managing the database.

*   **Simulation Engine (`main.py`)**: The central orchestrator. It initializes the league, runs the game loop (seasons, weeks, days), and calls other modules to process matches and finances.
*   **API (`api_fastapi.py`)**: A FastAPI application that serves data to the frontend. It provides endpoints for retrieving teams, players, match results, and season reports.
*   **Database (`football_sim.db`)**: An SQLite database used for persisting game state (players, teams, match history, manager stats).
*   **Modules**: The logic is split into domain-specific modules (e.g., `player.py`, `match.py`, `transfer.py`) each with a corresponding `*_db.py` file for database operations.

### 2. Frontend (React)
Located in the `frontend/` directory, this is a Single Page Application (SPA) built with:
*   **React**: UI library.
*   **Vite**: Build tool and dev server.
*   **Tailwind CSS**: Styling.
*   **Zustand**: State management (inferred).

It visualizes the data generated by the backend, allowing users to see league tables, squad details, and match results.

## File Organization

### Root Directory (Backend & Logic)
*   **`main.py`**: Entry point for running the simulation CLI / script.
*   **`api_fastapi.py`**: Entry point for the backend API server.
*   **`db_setup.py`**: Scripts to initialize or reset the SQLite database.
*   **Domain Modules**:
    *   `player.py` / `player_db.py`: Player attributes, growth, and DB storage.
    *   `team.py` / `team_db.py`: Team management, budgets, and squads.
    *   `match.py` / `match_db.py`: Match simulation engine and history.
    *   `manager.py` / `manager_db.py`: AI manager logic and profiles.
    *   `transfer.py`: Transfer market logic.
    *   `league.py`: League table and schedule management.
*   **Reports**:
    *   `season_reports/`: JSON files containing summaries of simulated seasons.
    *   `match_reports/`: Detailed logs of individual matches.
    *   `transfer_logs/`: Logs of transfer market activity.

### `frontend/` Directory
*   **`src/`**: React source code.
*   **`public/`**: Static assets.
*   **`vite.config.ts`**: Frontend build configuration.
